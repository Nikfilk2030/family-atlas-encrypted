# Разработка и проверка

## Минимальная сборка

Нужен Python3.12+ и этот checkout

```sh
python3 scripts/build.py
python3 scripts/build.py --check
```

Вторая команда ничего не пишет и завершается с ошибкой, если `index.html` отсутствует или отстаёт от исходников. Сборка проверяет данные до записи и заменяет готовую страницу атомарно

Для просмотра откройте `index.html` вручную. При необходимости можно запустить локальный сервер:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Сервер не нужен самой странице и не публикует её в интернет

## Инструменты разработки

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

Браузерные тесты выбирают `ATLAS_CHROME_BIN`, установленный Google Chrome на macOS или Chromium из Playwright

```sh
# Если подходящего Chrome нет
.venv/bin/python -m playwright install chromium

# Linux без необходимых системных библиотек
.venv/bin/python -m playwright install --with-deps chromium
```

Для выбранного браузера можно задать `ATLAS_CHROME_BIN` как путь к исполняемому файлу. Автоматические проверки всегда headless и не должны фокусировать пользовательские окна

## Обычная правка

```sh
.venv/bin/python scripts/format.py --write
.venv/bin/python scripts/build.py
.venv/bin/python scripts/build.py --check
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
git diff --check
```

`format.py` без `--write` только проверяет формат JS/CSS. Python и JSON в него не входят

## Короткие проверки

```sh
# Независимость сборки, экранирование, ссылки на изображения и границы путей
.venv/bin/python -m unittest discover -s tests -p test_public_build.py -v

# Работа нажимаемых линий
.venv/bin/python -m unittest discover -s tests -p test_line_interactions.py -v

# Условные положения неизвестных дат
.venv/bin/python -m unittest discover -s tests -p test_unknown_time_placement.py -v
```

Короткий тест полезен во время правки, но перед публикацией требуется полный прогон. Число тестов не заменяет осмотр скриншота и проверку реального пользовательского действия

## Визуальная приёмка

- Общий обзор должен оставаться полноценным деревом с читаемыми семейными группами
- Проверьте затронутый масштаб, а не только максимальное приближение
- Сравните «Поколения» и «По годам», неизвестные даты и возврат из таймлайна
- Проверьте мышь, касание, клавиатуру и отличие тапа от панорамирования
- Убедитесь, что досье открыто, изменяет размер и не сбрасывает камеру
- Сохраняйте доказательства в `test-results/`, не в `src/` или `data/`

## CI и Pages

`.github/workflows/verify.yml` запускается на изменениях приложения, данных, сборщика, тестов и самого workflow, а также вручную. Нет cron или постоянного мониторинга. Изменения только документации не запускают браузерную проверку

CI использует Python3.12, закреплённые зависимости и изолированный Chromium на Ubuntu. Действия GitHub закреплены по commit SHA, токен workflow имеет только чтение содержимого

GitHub Pages сохраняет прежний режим: **`main`, корень `/`**. Текущий `index.html` коммитится вместе с изменёнными исходниками. Pages и проверка CI являются разными заданиями, не считайте сам факт публикации зелёным тестом

После разрешённого push:

1. Прочитайте результат `Verify atlas` для точного commit
2. Дождитесь завершения существующей Pages-публикации
3. Сверьте SHA-256 отданного HTML с локальным `index.html`
4. Проверьте на живой странице изменённое действие

Не заводите второй репозиторий, новый хостинг или ключи для этой операции
