# Публичная модель данных

`data/atlas.json` представляет **уже опубликованную** модель атласа. Это не копия полного служебного дела исследования и не набор новых подтверждённых биографий

## Основные разделы

| Раздел | Смысл |
|---|---|
| `people` | Самостоятельные семейные и исследовательские записи |
| `families` | Семейные группы и появления людей внутри них |
| `relationships` | Индивидуальные связи с основаниями, статусом и уверенностью |
| `sources` | Подписи, ссылки, типы и оговорки источников |
| `documents` | Атрибутированные изображения и ссылки на файлы |
| `comparisons` | Сопоставления разных записей, не автоматические слияния |
| `nationalities` | Сведения с собственным основанием |
| `reading_rules`, `presentation` | Правила чтения и уже принятые представления |
| `default_family` | Семья первого открытия |

## Люди

- `id` сохраняется буквально, менять имя не значит менять ID
- `kind: family` обозначает семейную запись, `kind: record` отдельную исследовательскую запись
- `birth` и `death` хранят исходную строку с её точностью, пустое значение остаётся неизвестным
- `dates` является подписью жизненного периода, не запасным полем для рождения
- `source_ids`, `note`, `origin_story`, `variants`, `record_matches` сохраняют атрибуцию, неопределённость и разные версии
- `living_status` не выводится из имени или примерного возраста

`P-0034` — семейный Ефим Иванович Сорокин с неизвестными датами. `C-0013` — отдельная военная запись1912. До подтверждения тождества годы, портрет, награда и биография кандидата не переносятся семейному человеку

## Семьи и связи

`families[]` содержит `parents`, `children`, `peers` и `related`. Все они ссылаются на существующие `people[].id`

`ancestors[]` имеет поля `family_id`, `through_person_id`, `status`, `note`. Через `through_person_id` одна личность связывает свои появления в двух группах. Это не новая родительская связь между двумя людьми

У индивидуальных записей `relationships[]` идентификатор называется **`relationship_id`**, не `id`. Концы связи находятся в `person_a_id` и `person_b_id`, смысл в `relationship_type`, основания и оговорки в `supporting_artifact_ids`, `status`, `confidence`, `rationale`

Не исправляйте неподтверждённые связи до «точных», чтобы упростить раскладку

## Неизвестные даты на карте

Пользователь разрешил приблизительное размещение неизвестных дат рядом с родственниками и своим поколением

В `graph_time.js` используется отдельная схема геометрии: ближайшие временные опоры по семейным связям, условный шаг поколения28лет и округление ориентира до десятилетия. Это **допущение раскладки**, не вычисленная дата рождения и не архивный вывод

- В исходном `birth` ничего не записывается
- `temporal.kind` остаётся `unknown`, `temporal.year` остаётся `null`
- Условный `placementYear` существует только у графического появления
- Группа подписана «Ориентир», «Даты неизвестны», человек «Дата рождения неизвестна», «Положение условное»
- Связи возможного тождества не используются как доказательство даты
- Без временных опор показываются поколения без числовой шкалы
- Отдельный список «Таймлайн» сохраняет неизвестные рождения неизвестными

## Изображения

В исходном JSON у `documents[]` вместо длинного base64 стоят:

```json
{
  "media_type": "image/jpeg",
  "asset": "assets/documents/sorokin-24857097-award.jpg"
}
```

Это только фрагмент существующей записи. Её `person_id`, `kind`, `identity_status`, `title`, `caption`, `alt` и `source_url` не удаляются

Поддерживаются JPEG и PNG. Сборщик проверяет сигнатуру, путь внутри `assets/` и существование файла, затем создаёт `data_uri` в памяти для автономного HTML

Скан документа, портрет человека, индексная карточка и декоративная иллюстрация не взаимозаменяемы. Изображения кандидата сохраняют `identity_status: unconfirmed` и принадлежат кандидату, а не семейной записи

## При добавлении факта

1. Прочитайте имеющуюся запись и её источники, не создавайте дубль знакомого имени
2. Добавьте основание, сохраните противоречия и точность даты
3. Проверьте, что все ссылки ведут на существующие IDs
4. Для новой личности или источника обновите осмысленные ожидания тестов, а не только числовой итог
5. Пересоберите HTML и проверьте нужное досье и дерево
