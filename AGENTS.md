# Инструкции для агентов

## Точка входа

Это исходники **существующего** публичного атласа на GitHub Pages, не заготовка нового сайта

1. Прочитай `README.md`, `docs/ARCHITECTURE.md` и нужный раздел `docs/DATA_MODEL.md`
2. Выполни `python3 scripts/build.py --check`, чтобы увидеть, соответствует ли опубликованный HTML исходникам
3. Редактируй `src/` или `data/atlas.json`, затем форматируй, собирай и проверяй

`index.html` генерируется. Не исправляй JS/CSS внутри него вручную

## Команды

```sh
# Только сборка, без зависимостей и сети
python3 scripts/build.py
python3 scripts/build.py --check

# После установки requirements-dev.txt в .venv
.venv/bin/python scripts/format.py --write
.venv/bin/python scripts/build.py
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

Браузерные тесты работают изолированно и headless. Не открывай и не фокусируй пользовательские окна для автоматической проверки

## Что нельзя менять молча

- Не переименовывай этот репозиторий и не заводи другой хостинг
- Не возвращай шифрование, ключ в URL или аккаунт для чтения без нового поручения
- Не меняй принятую композицию дерева целиком ради локального улучшения
- Сохраняй цвета родства, поддеревья, масштабные уровни, досье, клики по линиям и отдельные камеры двух режимов
- Не нормализуй имена, идентификаторы и приблизительные даты догадкой
- `kind: family` и `kind: record` различают сущности, совпадение имени их не объединяет
- `P-0034` и `C-0013` остаются разными людьми до установления тождества, портрет и награды кандидата не принадлежат семейной записи автоматически
- Пол и национальность требуют собственного явного основания, фамилия или родственник его не заменяют
- Не восстанавливай закрытые/замаскированные адреса на сканах

## Время и линии

Рождение берётся из `birth`, не из `death` или общего `dates`

Пользователь отдельно разрешил **условное размещение** людей без дат около родственников и своего поколения. `placementYear` хранится только в геометрии `graph_time.js`, не в модели рождения. Подписи «Ориентир», «Даты неизвестны», «Положение условное» обязательны. Если временных опор нет вообще, показывай поколения без выдуманных числовых лет

Линия между двумя семейными группами может показывать **того же человека в двух группах**, а не новую связь родитель–ребёнок. Не смешивай её с реестровыми родительскими связями

При изменении маршрутов проверяй реальные непрозрачные карточки на каждом масштабе, входы в обе группы и попадание мышью/касанием. Перетаскивание линии должно оставаться панорамированием. Совпавшие линии дают выбор, не случайного человека

## Данные и изображения

`data/atlas.json` уже содержит опубликованную presentation-модель, а не закрытые первичные реестры. Ссылки и статусы источников сохраняются

Изображения находятся в `assets/documents/`, запись `documents[]` ссылается на `asset` и `media_type`. Сборщик встраивает их обратно в `data_uri` автономной страницы. Не добавляй base64 вручную в JSON

Не копируй сюда папку исследования, профили Hermes, `.env`, access-state, ключи и другие личные материалы. Публичность дерева не разрешает такую публикацию или поиск современных контактов живых людей

## Приёмка изменения

- Собранный `index.html` соответствует текущим исходникам
- Проверки прошли на **этой** сборке, а не на старом файле
- Для UI осмотрены скриншоты общего обзора и затронутого действия, в том числе на телефоне
- Тестовые артефакты остаются в `test-results/`, они не коммитятся
- Проверен `git diff --check` и список добавляемых файлов
- Публикация выполняется только по действующему поручению владельца
- После публикации читается реальный Pages-URL и проверяется доставленный HTML, одного `git push` недостаточно

Новый UI-тест не заменяет проверки остальных действий. Не ослабляй утверждение о данных или приватности ради зелёного CI. Если изменилось требование пользователя, сначала зафиксируй его, затем измени именно соответствующее ожидание
